# wipeme v0.2.1-alpha.1

Status: preview release.

## User-visible changes

- `wipeme --qr` prints a compact terminal QR code below the newly created private
  link.
- `wipeme --qr --qr-invert` renders a light-on-dark QR code for terminals or
  recordings where the inverse presentation scans more reliably.
- The private link remains the first stdout line. Without `--qr`, output is
  unchanged from `v0.2.0-alpha.1`.
- `--qr` cannot be combined with `--json`, preserving a stable machine-readable
  stdout contract. `--qr-invert` requires `--qr`.

Automatic-key QR codes contain the complete private link, including the fragment
secret. Screenshots, recordings, logs, and streams containing one grant access to
the message and must be handled as secrets. Manual-passphrase QR codes contain only
the public link; the recipient still needs the separately shared passphrase.

## Compatibility

- Encrypted envelope: v1, unchanged.
- Go SDK: `github.com/wipe-me/sdk/go@v0.5.0-alpha.1`, unchanged.
- Backend API: unchanged.
- Link formats: automatic `3-3-3#3-3-3-3` and manual `4-4`, unchanged.
- Supported release targets: macOS and Linux on AMD64 and ARM64.

## Release validation

- Run `go test ./...` and `go vet ./...`.
- Confirm `wipeme --version` reports `0.2.1-alpha.1-dev` before tagging.
- Confirm a tagged build reports exactly `0.2.1-alpha.1`.
- Create both normal and inverted QR output and scan each from a terminal or
  asciinema playback.
- Confirm `wipeme --json --qr` fails without contacting the service.
- Verify the GitHub archives, Homebrew cask, `.deb`, `.rpm`, APT preview repository,
  and RPM preview repository all contain the tagged binary.
