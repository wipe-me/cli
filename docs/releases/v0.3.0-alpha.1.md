# wipeme v0.3.0-alpha.1

Status: development preview.

## User-visible changes

- Adds `wipeme mcp`, a local stdio Model Context Protocol server implemented with
  the official Go MCP SDK `v1.7.0`.
- Exposes the fifteen agent-safe tools specified in `docs/mcp-server-v1.md`.
- Adds recovery-safe `consume_into_env_file`, `retry_into_env_file`, and
  `generate_secret_into_env_file` tools with dotenv, Docker, POSIX shell, and
  systemd encoders.
- Adds non-secret format markers and evidence-ranked format autodetection across
  complete existing env files, with `dotenv` as the stable shared-grammar tie-breaker.
- Adds a validated `message_filename` option to `consume_into_files` and
  `retry_into_files`, with deterministic attachment collision handling.
- Makes reusable private environment files the recommended agent execution path,
  particularly for repeated commands, retries, Docker, and Docker Compose; direct
  process injection remains available for a deliberate single execution.
- Does not expose direct plaintext reading, arbitrary commands, shell execution,
  raw passphrases, process output, clipboard access, or per-call server URLs.
- Defaults local stdio MCP to host-governed filesystem and inherited-environment
  access, with `--access restricted` and `mcp.access_mode: restricted` available
  for additional Wipe.me-managed roots and environment allowlists.
- Adds `wipeme mcp --show-policy` to print the resolved non-secret access mode,
  source, active allowlists, and operational policy as JSON without starting MCP.
- Adds mandatory process profiles, private recovery records, bounded retries, and
  generated-message cleanup in both access modes.
- Adds deterministic normal black-on-white inline PNG QR output for creation tools.
- Keeps the human CLI, v1 encrypted envelope, link formats, SDK version, and backend
  API unchanged from `v0.2.3-alpha.1`.

Private links and QR images returned through MCP are bearer capabilities and may be
retained by the host transcript. Decrypted text, generated secrets, attachments,
environment values, and process output are never returned by MCP tools.

## Compatibility

- Encrypted envelope: v1, unchanged.
- Go SDK: `github.com/wipe-me/sdk/go@v0.5.0-alpha.1`, unchanged.
- MCP Go SDK: `github.com/modelcontextprotocol/go-sdk@v1.7.0`.
- Backend API: unchanged.
- Link formats: automatic `3-3-3#3-3-3-3` and manual `4-4`, unchanged.
- Transport: local stdio only.
- Supported release targets: macOS and Linux on AMD64 and ARM64.

## Release validation

- Run `gofmt`, `go test ./...`, `go test -race ./...`, and `go vet ./...`.
- Confirm all fifteen tools and their input/output schemas through an MCP client.
- Confirm host mode works without Wipe.me path/environment allowlists and
  restricted mode enforces its configured roots and environment allowlists.
- Confirm `--access` overrides `mcp.access_mode` and invalid modes fail at startup.
- Confirm no direct-read or plaintext-returning tool is registered.
- Verify all four environment-file encoders and recovery-safe retries, including
  Docker multiline refusal and generated-link withholding until output succeeds.
- Run create, consume, retry, process, deletion, recovery and QR tests against the
  local development network.
- Decode inline PNG QR output independently and compare the complete private link.
- Inspect MCP protocol, process, Docker and backend logs for canary secrets.
- Confirm `wipeme mcp --version` reports `0.3.0-alpha.1-dev` before tagging and the
  tagged binary reports exactly `0.3.0-alpha.1`.
- Build a GoReleaser snapshot and inspect archives, Homebrew, `.deb`, and `.rpm`
  artifacts on macOS/Linux AMD64/ARM64.
